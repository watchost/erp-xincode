## 一、测试执行情况（如实记录，请先读这一节）

**本机没有可用的 PostgreSQL**：未安装 Docker，没有 PostgreSQL 服务，`localhost:5432` 无法连接。测试辅助代码 `internal/testsupport.NewDB` 在连不上数据库时会调用 `t.Skip`，所以：

- 本次新增的 8 个集成测试在本机**全部为 SKIP**，**没有真正执行，不能算作通过**。
- 原有的集成测试（销售、采购、仓库、生产等）在本机同样是 SKIP。之前汇报的"30+ 测试全部通过""go test 全部通过"，指的只是"没有失败"，**不代表这些测试真的跑过**。
- 要真正验证，需要满足以下任一条件：
  - 在 CI 中运行（`.github/workflows/ci.yml` 的 `backend-test` 任务会启动 `postgres:15-alpine`）；
  - 本机设置 `TEST_DATABASE_DSN`，或配置 `TEST_DB_HOST` / `TEST_DB_PASSWORD`，指向可用的 PostgreSQL 15。

其他检查：

- `go build ./...`：通过，退出码 0。
- `go vet ./...`：通过。
- `go test -count=1 ./...`：退出码 0，没有失败，但集成测试全部为 SKIP。
- 上一轮全量运行时退出码显示为 `4294967295`（即 -1），原因已查清：当时把 `go test` 的输出通过管道交给 `Select-String` / `Select-Object -First N` 截断，PowerShell 记录的是管道的退出状态。这次把输出重定向到文件，再读取 `$LASTEXITCODE`，实际退出码为 0。
- 排查中还发现另一个检查方法上的问题：`go vet ... | Select-Object` 之后再判断 `$LASTEXITCODE`，同样会受管道影响，曾经把编译失败误报为 `VET_OK`。本记录中的结论都是改为"重定向到文件后取退出码"重新跑出来的。

## 二、逐条修复

| # | 缺陷 | 修复方式 | 对应测试 |
|---|---|---|---|
| 1 | `GetCostVariance` 中实际成本写死为"标准成本 × 1.05" | 实际成本先取完工入库单的加权单价（`ProductionReceiptRepository.GetAvgUnitCostByMaterialID`），没有时再取库存的加权平均成本；两者都没有时返回 `50007 / 400 无实际成本数据`，不再编造数值 | `TestCostVariance_NoActualCostReturns50007`、`TestCostVariance_UsesRealInventoryCost` |
| 2 | `explodeNode` 中末级物料成本写死为 10 | 改为取库存加权平均成本（`WarehouseService.GetMaterialAvgCost`）。没有成本数据时记为 0 参与卷算，不再编造 10。**待办**：BOM 树节点还没有"成本待定"标记字段，调用方目前无法区分"真实成本为 0"和"缺少成本数据" | 原有的 `TestBom_Explosion_And_CostRollup`（本机 SKIP）；没有新增专门测试 |
| 3 | `POST /finance/receivables`、`POST /finance/payables` 挂的是查看权限 | 新增权限 `finance:receivable:create` 和 `finance:payable:create`，路由改为使用这两项。**授权写在新迁移 `0020` 中，已发布的 `0019` 已恢复原样，没有改动** | 没有自动化测试（路由层没有 HTTP 测试框架），需要人工或 CI 验证 |
| 4 | finance handler 中写的是字面量 `"user_id"` | 统一改为 `middleware.CtxUserID` | 编译通过；没有专门测试 |
| 5 | 销售出库、采购入库不生成应收单、应付单 | `Poster` 接口新增 `CreateReceivableTx` / `CreatePayableTx`。销售出库在确认应收的同一事务中写入 `fin_receivable`，采购入库在同一事务中写入 `fin_payable`，付款期限默认 30 天。订单模型目前没有 `TenantID` 字段，这部分留给多租户任务（任务 3）处理 | 4 个测试：单据生成，以及"生成失败时整个事务回滚"的故障注入 |
| 6 | 盘点新物料单位成本为 0，审批时生成 0 金额凭证 | 录入实盘时，对账面上没有的物料补取加权均价；审批盘盈时成本仍为 0 的，以 `40003` 拒绝审批；只有金额大于 0 的明细才生成分录，不再产生 0 金额凭证 | `TestStockCheck_ZeroCostGainRejected` |
| 7 | `DeductQty` 没有任何地方调用，批次余量与出库脱节 | `ApplyOutboundTx` 在同一事务中按先到期先出（FEFO，`expired_at ASC NULLS LAST`）扣减批次余量，查询批次出错时直接返回错误，不再忽略。**限制**：批次余量不足时，只扣到 0，剩余出库数量视为未纳入批次管理的库存，不会拦截出库 | `TestOutbound_DeductsBatchesFEFO` |
| 8 | 只有 CSV 工具函数，打印功能没有接口，也没有条码 | 新增物料、客户、供应商的 CSV 导入和导出接口：`/mdm/{materials,customers,suppliers}-{export,import}`；新增打印接口 `POST /print/document`，以及条码接口 `GET /print/barcode`（Code 128，输出 SVG）。**说明**：只支持 CSV（带 UTF-8 BOM），**不支持 .xlsx**；供应商表没有电话和地址字段，所以只导入导出编码、名称、联系人三列；条码**没有用扫码枪或 PDA 实际扫过，未经验证** | 没有新增测试；`internal/pkg/printer` 包内原有测试可以通过 |
| 9 | 根目录的 `server.exe` | 核实结果：`git ls-files server.exe` 没有输出，说明它没有被 git 跟踪；`git check-ignore` 显示它已被 `.gitignore:27 *.exe` 规则忽略，**不需要改动** | — |
| 新增 | warehouse 角色缺少 `mdm:warehouse`、`mdm:location`、`mdm:material` 三项权限，导致仓库角色登录 PDA 后无法使用 | 授权写在 `0020` 中，使用 `ON CONFLICT DO NOTHING`，可以重复执行；回滚脚本只撤销这三项授权 | 没有自动化测试 |
